# Architecture

The opt-in release checker and MSI installer handoff are described in [update architecture](UPDATES_ARCHITECTURE.md) and [update behavior](UPDATES.md). Their network/timer work is independent of the keyboard callback and window-management path.

`LoginStartup` in the Windows project manages an explicit HKCU Run opt-in through a testable store. The application shares one `LoginStartupViewModel` between General and the tray. It reads on menu opening/window activation and writes only on explicit toggles; no polling, watchers or JSON duplication. Unlike the layout/shortcut draft, this OS preference changes immediately and is labeled accordingly. Uninstall deletes the value only when it matches the installed executable.

- `PaneShift.Core` (`net10.0`): physical-pixel rectangles, pure geometry and gap transform, separate command repetition state, half-size and horizontal-position cycle strategies, action identifiers, hotkey/settings models, portable JSON file persistence, original window geometry history. `RuntimeSettings` owns the immutable active snapshot and the repetition state it resets when committing a valid candidate. No platform API calls.
- `PaneShift.Windows` (`net10.0-windows`): Win32/DWM P/Invoke, foreground-window and monitor work-area retrieval, window placement, visible-frame compensation, global hotkey lifecycle, command-failure translation, current-process elevation detection, and explicit restart handoff.
- `PaneShift.App` (`net10.0-windows`): WPF lifecycle, message-only HWND, settings path/loading and Explorer integration, centralized icon loading. Windows Forms supplies only the notification icon and its menu. No external window-management dependencies.
- `PaneShift.Core.Tests`: xUnit geometry, partition coverage, repetition/reset, gap adjacency, history, settings persistence/validation, runtime reload and shortcut tests.
- `PaneShift.Windows.Tests`: deterministic tests for native-error classification, failure/reset behavior, restart arguments, launch configuration and UAC-cancellation mapping; no elevated target is required.

`SettingsStore.LoadCandidate()` reads and validates without changing live state. `ConfigurationActivation` is the shared GUI Apply / explicit Reload pipeline. `GlobalHotkeys.Transition` keeps current chords reserved while acquiring every new chord, reuses reservations for action swaps, then runs the commit. GUI commit writes a flushed sibling temporary file and atomically replaces the JSON before swapping the runtime snapshot and dispatch map. A conflict or file error releases only newly acquired reservations; old working registrations, active settings and file remain intact. Reload uses the same transition without writing the file. Rare native unregister errors remain visible in status; unused retained reservations never dispatch an action. Startup and resume retain the existing partial-success policy because no working active registration map exists then.

`RuntimeSettings.ReplaceCurrent()` commits on the message-window thread and resets repetition. `WindowService` stays alive, retaining Restore history. Core owns the catalog, chord codec and immutable settings; Windows owns native registration and the activation coordinator. App owns `SettingsViewModel`, the draft/validation state, `ShortcutRecorder`, lightweight WPF glyphs and `SettingsWindow`. The view calls application callbacks, never Win32. Windows Forms remains limited to the tray. No additional UI packages or file watchers are introduced. The optional release checker has one due-time dispatcher timer; window management and keyboard translation do no background polling. The opt-in translation hook is described below.

Layouts use rational boundaries relative to the active window's monitor **work area**, preserving taskbar space. Each integer boundary is `size * numerator / denominator`, with 64-bit intermediate arithmetic. Adjacent regions share boundaries, avoiding gaps at odd widths. Center Two Thirds spans 1/6 to 5/6. Rounding differences are at most one pixel. Degenerate zero-sized tiles are rejected.

The executable declares Per-Monitor V2 DPI awareness. All native geometry uses physical desktop pixels, including negative origins; WPF device-independent units never enter the geometry engine. DWM visible frame bounds compensate for invisible resize borders, falling back to the outer rectangle when unavailable. The manifest establishes DPI awareness before WPF startup. The Forms-only analyzer advice WFO0003 is explicitly suppressed with an explanation in the project because Forms does not own application startup.

Before the first modification, the service saves original geometry and native placement per HWND. Subsequent tiles preserve that original state. `Restore` is implemented in the service using the original placement, including maximized state, but has no default shortcut. History lives only for the current session. Closed windows and handles reused by another process/thread are pruned on the next action; reuse within the same process/thread remains a limitation until lifecycle tracking is added.

## Mac-style shortcut translation

The optional Swiss Right Alt+G feature shares this input service. Its immutable
`KeyboardShortcutConfiguration` also routes configured Ctrl+Alt window bindings
through the hook while excluding Right Alt, preserving native AltGr characters.
Without that option, window commands continue using RegisterHotKey as described
below. See [Swiss keyboard routing, Unicode and validation](KEYBOARD_ALTGR.md).

Core owns the immutable `MacStyleShortcutSettings` (off by default), fixed `ShortcutTranslation` catalog, and cross-validation against configured window hotkeys. App adds a Keyboard tab to the existing draft view model; no Win32 code enters WPF view code. The existing window action bindings, repetition and geometry are unchanged.

### Why an optional hook is necessary

A native RegisterHotKey probe on the development Windows desktop (2026-09-30) attempted every source chord with MOD_NOREPEAT, releasing successful registrations immediately. Eleven failed with error 1409 (already registered), including Win+C/V/X/A/Z/S/F/T/W/Q and Win+Shift+T; only Win+Shift+Z succeeded. Therefore RegisterHotKey cannot reliably supply the complete override. Microsoft documents [Win-key combinations as reserved for the OS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey). Splitting the whitelist across both mechanisms would complicate semantics without removing the need for a hook.

`MacStyleShortcutService` installs WH_KEYBOARD_LL only while either keyboard option is enabled, on a dedicated message-pump thread. It does not inject a DLL, poll, call application UI from the callback, or block on file/network I/O. Default window commands retain the existing RegisterHotKey subsystem; the Swiss option selectively routes Ctrl+Alt chords as described above. The callback passes unrelated keys, extra modifiers and all injected events onward; it consumes only matched down/repeat/up events. An outstanding-key bitset prevents auto-repeat and orphan source key-ups, even if Win is released first. No text, key history or activity log is retained. Injected events are excluded before matching to prevent recursion. Windows may remove a hook that exceeds its timeout, so keeping the callback independent of WPF dialogs/file saves matters; see [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc).

`ConfigurationActivation` prepares an inactive hook alongside native registrations. After successful atomic file save and runtime commit it activates the entire whitelist. Failed hook installation, registration or save releases only preparation and preserves existing execution. Disabling, pause and disposal turn off interception and stop the hook thread. Paused Apply validates installation without activating input. Internal source conflicts are rejected before touching either layer. Startup/resume retain partial success for legacy window registrations; the translation whitelist is all-or-none. Third-party hook precedence cannot be reliably reserved or diagnosed like RegisterHotKey conflicts.

### Balanced input and privileges

`ShortcutInputSender` uses a single SendInput batch: mask the Start-menu gesture with an unassigned VK (0xE8), release held left/right Win and Shift, press only target modifiers, press/release the target, release target modifiers, restore physical Win/Shift, and mask the restored Win gesture. The destination key therefore has no Win modifier and Shift only when mapped. Restoring physical modifiers allows another native chord while Win is still held; the subsequent physical release completes their lifetime. Both Windows keys and both Shift keys are covered. A partial SendInput result triggers a best-effort recovery batch based on the accepted prefix, without retrying the action. Zero/partial acceptance posts a status message to App, which reports the failure outside the hook. Recovery can itself be denied by Windows; protected desktops are not bypassed.

Win+W is suppressed before shell handling and translates to Ctrl+W; the application determines tab/document behavior. Win+Q translates to Alt+F4, without Process.Kill, TerminateProcess, arbitrary WM_CLOSE or process enumeration. No forceful close is involved. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) is subject to UIPI and sends to the foreground application. Standard PaneShift cannot send to higher-integrity targets; the existing explicit UAC restart remains the only supported elevation path. A foreground change during delivery or software that handles raw input differently remains a Windows/application limitation. Pause shortcuts for incompatible games or other keyboard tools.

# Update architecture

`ReleaseUpdates` in Core validates the fixed repository's stable versions, filenames, URLs and asset digests. `ReleaseClient` in Windows has a bounded, cancellable HTTP path, exact HTTPS redirect host allowlist, streaming size/hash verification and partial-file cleanup. `UpdateCheckStore` persists only attempt time and last notified tag separately from user settings.

`UpdateViewModel` in App serializes manual/automatic requests, exposes status and release notes, handles errors without modal check dialogs and never installs during a check. General's flag is part of the existing Settings draft. App configures the shared view model after valid Apply/reload, schedules one due-time dispatcher timer, cancels automatic requests on opt-out and all requests on exit. Disabled defaults construct no network request.

On explicit installation, `UpdateInstaller` relocates the current app/runtime to a private GUID staging directory, writes a constrained job, starts the helper mode and lets the parent exit normally. Helper mode is handled before mutex, shortcut registration or update scheduling. It validates the job's location, package filename/hash, version and installed source, checks process ID plus start time, waits for exit, opens Windows Installer and verifies/relaunches the installed version. Portable copies receive a ZIP with manual extraction; elevated instances cannot install.

Installer custom actions are a separate net48 project, never loaded by WPF. MSI owns its payload/components, shortcut and per-user installation marker. Startup deletion is deferred, user-impersonated and conditional on the exact installed executable; rollback restores the original command only if still absent. Major-upgrade removal skips startup deletion. Legacy Inno cleanup is a commit action after the MSI transaction: the formats cannot be made atomic together, so incomplete cleanup is reported instead of deleting unrelated files or falsely rolling back the new MSI.

`InstallerInstanceLock` supplies `Global\PaneShift-<user SID>` to both app and installer. The MSI service can observe it across Windows sessions, while the app also retains `Local\PaneShift` for compatibility. Installer preflight checks older releases once by their exact default Inno executable path; it never terminates a process. `UserRegistry` opens the installing SID's loaded hive explicitly in the 64-bit view. Native AppSearch carries secure legacy-record properties and a hidden startup command snapshot from the interactive client when the service registry view differs. An available service Run value takes precedence over that snapshot; only an exact original legacy command permits redirection. Migration checks before and after Inno cleanup and verifies its own write, preserving off and foreign-copy preferences. All paths and commands are validated again before migration. An unreadable record with an existing legacy uninstaller fails safely before file installation.

Deterministic tests cover JSON defaults/persistence/rejection, draft state, stable versions and exact asset selection, cadence/clock rollback, network failures/cancellation/concurrency, redirects, streamed size/hash rejection, notifications, job boundaries and startup/migration policy. Real installer, privileges, helper relaunch and external release scans are acceptance checks with separate evidence.
